# 06. 狩猟素材の獲得・劣化・流通・個人依頼 設計

> 状態：**設計案**（未実装）。数値はすべて仮で、プロトタイプとシミュレーションで調整する。
> 方針：最初は「素材データ・獲得方法・時間経過・取引の土台」だけを作る。ギルド・オークション・個人依頼などは、その土台の上に後から追加する。

---

## 0. 全体像

```
 討伐 ─→ 死体(Carcass) ──┬─ 剥ぎ取り ───→ 素材(ItemInstance)
          │ 部位ごとに鮮度   ├─ 部分搬送 ───→ 部位(PartCargo) ─→ 街で解体 → 素材
          │ が時間で低下     └─ 全体搬送 ───→ 死体ごと(CarcassCargo) ─→ 街で解体/研究 → 素材＋特別報酬
          ▼
 素材(ItemInstance)：出自（どのモンスター・どの方法・いつ・誰）と鮮度を記録
          ▼
 流通チャネル：ジョブギルド / 直接取引 / ブラックマーケット / 月例オークション / 個人依頼
          ▼
 需要：飲食店・鍛冶師・錬金術師・商人・NPC → 加工・調理・製造 → 製品として再流通
```

全チャネルは、**共通の「所有権・通貨台帳」**（サーバー側DB）の上で動きます。チャネルごとに異なるのは手数料・条件・リスクだけです。そのため、新しいチャネルは「ルールの追加」で増やせます。

## A. 素材獲得方式ごとの素材テーブル

### A-1. 基本の考え方
- 3方式は**倍率の違いではなく、手に入る素材そのものが異なる**。
- 方式ごとに「その方式でしか手に入らない素材（専用素材）」を必ず1つ以上持たせる。

| 方式 | 手に入りやすい素材の性質 | 専用素材の例 | 代償 |
|---|---|---|---|
| 剥ぎ取り | 小さく、その場で切り取れるもの・損傷していても取れるもの | 鱗片、爪の欠片、脂（少量） | 部位の形を保てない／希少器官は傷みやすい |
| 部分搬送 | 「形のまま」価値がある部位 | 完全な角、大判の皮、無傷の牙、生きた臓器 | 荷車と重量制限、帰り道の危険 |
| 全体搬送 | 死体全体の状態に依存するもの・研究価値 | 骨格一式、大量の血液、全身標本、研究報告（報酬金＋情報） | 人数・時間・設備・費用が大きい |

### A-2. 部位（Part）を中心にしたデータ構造

素材テーブルは「モンスター → 部位 → 方式」の順で定義します。

```
MonsterLootProfile（モンスターごと）
 ├ species_id           : モンスター種別
 ├ parts[]              : 部位リスト
 │   ├ part_id          : 頭/角/胴/尾/翼/内臓…
 │   ├ weight_kg        : 搬送時の重量
 │   ├ volume           : 搬送時の容積
 │   ├ decay_class      : 劣化の速さの区分（B章）
 │   ├ breakable        : 部位破壊の有無
 │   └ harvest_slots    : 剥ぎ取り可能回数
 └ loot_entries[]       : 素材の出現ルール
     ├ method           : HARVEST / PART_TRANSPORT / FULL_TRANSPORT
     ├ part_id          : どの部位から（全体搬送は "WHOLE"）
     ├ material_id      : 得られる素材
     ├ qty_min / qty_max
     ├ chance           : 出現確率
     ├ conditions       : 部位破壊済み/未破壊、討伐方法（捕獲/毒殺など将来）、必要な道具・職業
     ├ yield_curve      : 鮮度→取得数量の補正（B章）
     └ quality_curve    : 鮮度→品質上限の補正（B章）
```

### A-3. サンプル：大型猪型モンスター「ガルドボア（仮）」

| 方式 | 部位 | 素材 | 数量 | 条件・備考 |
|---|---|---|---|---|
| 剥ぎ取り | 胴 | ガルドボアの剛毛 | 2〜4 | 常に取得可 |
| 剥ぎ取り | 牙 | 牙の欠片 | 1〜2 | 牙が**破壊済み**だと確率アップ |
| 剥ぎ取り | 胴 | 獣脂（少量） | 1 | 鮮度で数量が減る |
| 部分搬送 | 牙 | **完全な大牙** | 1〜2 | 牙が**未破壊**であること（部分搬送専用） |
| 部分搬送 | 胴 | **大判の硬皮** | 1 | 剥ぎ取りでは取れない |
| 部分搬送 | 腿 | **ボア腿肉（塊）** | 1 | 劣化が速い。飲食店向け |
| 全体搬送 | WHOLE | **ボアの骨格一式** | 1 | 全体搬送専用。鍛冶・研究向け |
| 全体搬送 | WHOLE | **鮮血（樽）** | 1〜3 | 討伐から短時間で街に着いた場合のみ。錬金術向け |
| 全体搬送 | WHOLE | 研究報告書（報酬金） | - | 研究所への納入。死体の損傷度で金額が変わる |

部位破壊は「剥ぎ取りには有利、部分搬送には不利」になることがあります。そのため、**戦闘の段階から持ち帰り方を意識した戦い方**が生まれます。

## B. 素材の時間経過（劣化）

### B-1. 2つを別々に管理する
| 対象 | 管理単位 | 説明 |
|---|---|---|
| 死体（Carcass） | **部位ごと**の鮮度 | 討伐時点から開始。環境（気温・天候・水中など）の影響を受ける |
| 取得済み素材（ItemInstance） | 素材の束（ロット）ごとの鮮度 | 取得した時点の鮮度を引き継ぎ、その後は**素材ごとの劣化速度**と保管環境で変化 |

例：死体の腿肉が鮮度80の状態で切り出した場合、腿肉は鮮度80から始まり、以後は「生肉」の速度で劣化する。

### B-2. 劣化区分（decay_class）
| 区分 | 例 | 劣化の速さ（仮） |
|---|---|---|
| 不朽 | 骨、角、鉱物化した鱗 | 劣化しない |
| 遅い | 皮、毛、爪 | 数日で品質が少し下がる |
| 普通 | 脂、腱 | 1日程度 |
| 速い | 生肉、内臓 | 数時間 |
| 非常に速い | 血液、特殊器官、毒腺 | 数十分〜1時間 |

一部の素材は時間で**良くなる**ようにすることもできます（例：熟成肉）。その場合は鮮度とは別に「熟成度」を持たせます（将来）。

### B-3. 鮮度の影響
- **取得数量**：死体の鮮度が低いと、剥ぎ取りや解体で取れる量が減る（`yield_curve`）
- **品質上限**：鮮度が低い素材からは高品質の製品を作れない（`quality_curve`）
- **段階表示**：プレイヤーには数値ではなく「新鮮／良好／劣化／腐敗」で見せる（腐敗した素材は別の素材「腐肉」などに変化させてもよい）

### B-4. 劣化を抑える手段
| 手段 | 効果（仮） | どこで |
|---|---|---|
| 冷却箱（携帯） | 速度 ×0.5 | 探索中・搬送中 |
| 冷却設備（荷車オプション） | 速度 ×0.3 | 搬送中 |
| 保存庫・氷室 | 速度 ×0.2 | 街・住宅 |
| 加工（塩漬け・燻製・なめし・乾燥） | **別の素材に変換**し、劣化をほぼ止める | 加工設備 |

加工すると劣化は止まりますが、生の状態でしか使えない用途は失われます（例：鮮血は錬金術に使えるが、乾燥血粉は使い道が限られる）。
この仕組みにより、**加工職に「劣化を止めて価値を保つ」役割と利益**が生まれます。

### B-5. サーバー実装方針（負荷対策）
- 毎秒すべての素材を減らす処理は**行わない**。
- 各素材は「最後に状態が変わった時刻」「その時点の鮮度」「現在の劣化速度」だけを保存し、**参照するときに計算**する。
  ```
  現在の鮮度 = 記録時の鮮度 − 劣化速度 × 保管補正 × (現在時刻 − 記録時刻)
  ```
- 保管場所が変わったとき（冷却箱に入れたなど）だけ、その時点の鮮度を確定して記録し直す。
- この方式なら、数百万個の素材があってもサーバー負荷はほぼ増えません。

### B-6. ロット（束）の扱い
鮮度や出自が違う素材を1つにまとめると、条件の判定ができなくなります。そのため、素材は「ロット」単位で管理します。
- 同じ素材・同じ取得方法・同じ品質帯・**近い取得時刻**のものだけを自動でまとめる。
- インベントリ上では1マスに複数ロットを重ねて表示し、使うときは「古いものから」を基本にする。

## C. 流通チャネル

### C-1. 共通の土台：所有権と台帳（サーバー側）
- **アイテムの状態**：`所持中 / 出品中(ロック) / 預かり中(エスクロー) / 搬送中 / 消費済み`
- **通貨**：すべての増減を台帳に記録する（誰から誰へ・理由・関連する取引ID）。所持金の数値を直接書き換える処理は作らない。
- **取引の確定**：「検証 → DBで一括確定 → 結果通知」。途中で失敗したら全部取り消す（素材の複製や消失を防ぐ）。
- **二重送信対策**：同じ取引要求が2回届いても1回分だけ処理する（取引ごとの一意ID）。
- **チャネルはルールで差を付ける**：手数料、出品料、決済タイミング、匿名性、出品制限、リスク。

### C-2. チャネル比較（初期案）
| チャネル | 手数料(仮) | 決済 | 安全性 | 特徴・リスク | 実装段階 |
|---|---|---|---|---|---|
| ジョブギルド | 5〜10% | 即時 | 高 | 職業に関係する素材のみ。NPCの買取価格（底値）＋プレイヤーの委託販売。取引するとギルドでの評価が上がる | 第5段階 |
| プレイヤー間直接取引 | 0〜2% | 即時（双方が確認） | 高（取引画面の中だけ） | 取引画面の外での約束はシステムが保証しない | 第5段階（最初に実装） |
| ブラックマーケット | 15〜30% | 即時 | 低 | 規制素材・密猟品も扱える／相場の変動が大きい／**摘発による没収**の確率／勢力評価の低下／取引相手は匿名 | 第6段階以降 |
| 月例オークション | 出品料＋落札額の5% | 開催日に確定 | 高 | 希少品向け。入札時に金額を預かる。出品中の素材は**オークション側の保管庫で劣化停止**（または加工済み・不朽素材のみ出品可） | 第6段階以降 |
| 個人依頼（指定納品） | 掲載料＋成功報酬の数% | 納品時に自動 | 高 | E章を参照。報酬を事前に預かる | 第6段階 |

### C-3. 流通制限（既存仕様との整合）
- 装備品は、レベルやストーリー進行による**装備制限**をサーバーで判定する（買えても使えない／出品できない、など）。
- ストーリーを壊す品目は「取引不可」フラグを持たせる。ブラックマーケットでも扱わない品目を別に定義する。

## D. 素材を必要とするプレイヤー（需要）

### D-1. 職業と需要
| 職業 | 主な需要素材 | 作るもの | 狩猟者との関係 |
|---|---|---|---|
| 飲食店経営者（料理人系） | 肉、内臓、特殊食材、農作物 | 料理（狩猟前の強化効果）、店でのNPC向け販売 | **鮮度**を重視 → 部分搬送・冷却の需要 |
| 鍛冶師 | 鉱石、骨、角、牙、金属 | 武器・防具・道具・荷車部品 | **形状・品質**を重視 → 部位破壊を避けた部分搬送の需要 |
| 錬金術師（新規追加） | 特殊器官、毒腺、血液、希少素材 | 薬、属性付与、状態異常アイテム | **超短時間の鮮度**が必要 → 全体搬送・冷却設備の需要 |
| 商人 | 全般（特に希少品） | 流通・在庫・輸送 | 価格差・地域差・劣化リスクを引き受けて利益を得る |
| 農家 | 獣脂、骨粉（肥料） | 農作物 → 飲食店へ | 劣化した素材や余った素材の受け皿 |

これにより「**劣化した素材にも行き先がある**」状態を作り、全部が無駄にならないようにします。

### D-2. 循環の例
```
狩猟者 ─腿肉(鮮度高)→ 飲食店 ─料理(攻撃力アップ)→ 狩猟者
狩猟者 ─完全な大牙→ 鍛冶師 ─武器→ 狩猟者
狩猟者 ─鮮血→ 錬金術師 ─毒薬→ 狩猟者
劣化した肉・骨 → 農家(肥料) → 作物 → 飲食店
商人：街ごとの価格差、冷却輸送、オークション仕入れで利益
```

### D-3. 人数が少ない時期への対策
ベータ版はプレイヤー数が少ないため、**NPCによる需要と供給**を組み込みます。
- ギルドの常設買取（底値）
- NPCの客が飲食店を訪れる
- NPCの発注書（街の需要）

これらで最低限の流通を保ち、プレイヤーが増えたらNPCの比重を下げます。

## E. 個人依頼・個人クエスト

### E-1. 設定項目
| 項目 | 内容 | システムで判定できるか |
|---|---|---|
| 対象モンスター | 種別（個体指定は不可） | ○（素材に出自が記録されている） |
| 必要素材・数量 | 素材IDと数量 | ○ |
| 獲得方法 | 剥ぎ取り／部分搬送／全体搬送／指定なし | ○（出自に記録） |
| 品質 | 下限 | ○ |
| 鮮度 | **納品時点**での下限 | ○ |
| 報酬金 | 金額（事前に預かる） | ○ |
| 納品期限 | 日時 | ○ |
| 納品場所 | ギルドの納品窓口（初期）／依頼者の店・住宅（将来） | ○ |
| 公開範囲 | 全体／同じギルド／フレンド／指名 | ○ |
| 分納 | 可／不可 | ○ |
| 受注者の保証金 | なし／金額（受注者が預ける） | ○ |

**原則：報酬の支払いに関わる条件は、すべてシステムが自動判定できるものに限ります。**
自由記述のメモは書けますが、支払いの判定には使いません。これにより、紛争の大部分を最初から発生させません。

### E-2. 状態の流れ

```
 下書き → 掲載中 ─(受注)→ 受注中 ─(納品・条件OK)→ 完了（報酬を支払う）
            │                │
            │(取り消し)      ├(期限切れ)→ 期限切れ
            ▼                ├(依頼者が取り消し)→ 取り消し
          取り消し          ├(受注者が辞退)→ 掲載中に戻る or 取り消し
                             └(異議)→ 調査中 → 完了 or 返金
```

| 出来事 | 報酬金（預かり分） | 受注者の保証金 | 評価 |
|---|---|---|---|
| 完了 | 受注者へ（手数料を差し引く） | 返却 | 双方＋ |
| 受注前に取り消し | 依頼者へ返却（掲載料は戻らない） | - | 影響なし |
| 受注後に依頼者が取り消し | 依頼者へ返却。ただし**一部を受注者への補償**に回す | 返却 | 依頼者− |
| 受注者が辞退 | 依頼者へ返却 or 再掲載 | 一部を依頼者へ | 受注者− |
| 期限切れ（納品なし） | 依頼者へ返却 | 一部を依頼者へ | 受注者− |
| 分納の途中で期限切れ | 納品分を支払い、残りを返却 | 不足割合に応じて | 小さく− |

- 納品された素材は、条件判定に合格した時点で**即座に依頼者の所有に移り**、報酬が同時に支払われます（同じDB処理内で行う）。
- 不合格の素材は受け取りません（その場で返却）。

### E-3. 紛争と不正への対策
- 判定が自動なので、紛争は主に「バグ」「通信切断」によるもの。これは取引ログから運営が確認します。
- **資金移動の悪用**（ゴミ素材1個に大金を払うなど、RMTの資金移動）への対策：
  - 報酬額が相場から大きく外れる依頼を記録し、監視する
  - 新しいアカウントには報酬上限を設ける
  - 掲載料と手数料は必ず発生させる
- 受注の独占対策：1人が同時に受けられる依頼の数に上限を設ける。

## F. 経済システムとの連携

### F-1. 価値が生まれる場所（狩猟者以外も儲かる仕組み）
| 役割 | 利益の源 |
|---|---|
| 狩猟者 | 素材の販売、依頼報酬、研究報酬 |
| 運搬・護衛 | 搬送の手伝い報酬（パーティ内の分配や依頼） |
| 加工職 | 劣化を止めて価値を保つ（生の素材を安く買い、加工品を売る） |
| 飲食店・鍛冶・錬金 | 製品の付加価値（強化効果・装備） |
| 商人 | 地域差・時間差（オークション）・在庫リスクの引き受け |

### F-2. 価格を動かす要素
- **供給量と需要量**：ギルドの買取価格を、直近の取引量に応じて街ごとに変動させる（上下限あり）
- **劣化**：鮮度の低い素材ほど安い → 冷却・加工・素早い取引に価値が出る
- **加工コスト**：設備使用料、燃料、時間
- **輸送コスト**：荷車の耐久消耗、冷却材、護衛費、危険

### F-3. お金と物の「出口」（インフレ防止）
| 出口 | 種類 |
|---|---|
| 各種手数料・掲載料・出品料 | お金 |
| 家賃・許可証・治療費・修理費 | お金 |
| 素材の腐敗・ブラックマーケットでの没収 | 物 |
| 料理・薬の消費、装備の耐久消耗 | 物 |

経済の数値は、ゲームに組み込む前に**シミュレーションスクリプトで事前に検証**します（Claudeがクラウド上で作成・実行できる部分）。

## G. 実装の段階分け

| 段階 | 内容 | 対応マイルストーン |
|---|---|---|
| **今回（設計）** | 本書。データ構造・状態・ルールを決める | - |
