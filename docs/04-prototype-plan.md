# 04. 最初に作る技術検証用プロトタイプ

> 状態：**決定案**（ユーザー承認後に着手）

## プロトタイプ名：P1「ふたりで狩って持ち帰る」

仕様書の第1段階（技術検証）を中心に、本作の独自性である**討伐後の処理**の可否を最小限で確かめるところまでを1つのプロトタイプとします。
見た目はすべて仮（UE付属マネキンと箱・カプセル）です。

### なぜこの範囲か
- マルチプレイを後から入れると作り直しになるため、**最初から2人接続で作る**。
- 「剥ぎ取り／搬送」は既存ゲームにない本作の核であり、遊びとして成立するかを早く確認したい。
- 見た目を作り込む前に「通信・データ構造・サーバー権限」の土台を固める。

## マイルストーン（各項目が単独で動作確認できる単位）

| # | 内容 | 完了条件（あなたのPCで確認） | 種別 |
|---|---|---|---|
| M1 | UE5 C++ プロジェクト作成・Git管理開始 | エディタで開ける／GitHubにpushできる | 基盤 |
| M2 | 三人称キャラ操作＋カメラ切り替え（肩越し⇔遠景） | キー1つでカメラが切り替わる | 完成機能（仮見た目） |
| M3 | マルチプレイ接続（エディタ内でサーバー1＋クライアント2） | 2画面で互いの移動が見える | 完成機能 |
| M4 | 練習用モンスター（箱）：HP・被ダメージ・死亡をサーバーで処理 | 片方が攻撃→両画面でHPが減り倒れる | 仮実装（AIなし） |
| M5 | 簡易攻撃＋回避（GAS導入の検証） | 攻撃・回避がサーバー判定で同期 | 仮実装 |
| M6 | 剥ぎ取り：死体に近づき長押し→素材がインベントリへ | 回数制限あり、素材がサーバー側で付与 | 仮実装 |
| M7 | 部分搬送：部位を切り出して荷車に積む（重量上限） | 上限超過で積めない | 仮実装 |
| M8 | 全体搬送：2人で押すと動く荷車、街エリアの納品所で報酬計算 | 1人より2人で速い／3方式で報酬が異なる | 仮実装 |

M1〜M3 が仕様書の「第1段階」、M4〜M8 は第2〜3段階の**先行検証**です。
M4以降は「仮実装」であり、完成機能としては扱いません。

## このプロトタイプで判断すること
1. GASを採用し続けるか（学習コストに見合うか）
2. 荷車の簡略物理で協力搬送が楽しくなるか
3. 3つの報酬方式に「選ぶ理由」が生まれるか
4. ネット遅延（エディタの遅延シミュレーション機能で検証）下でも攻撃・搬送が破綻しないか
5. PCスペックが開発に十分か
